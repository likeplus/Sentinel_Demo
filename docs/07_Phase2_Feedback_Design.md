# Phase 2 试玩反馈版：产品与交互设计方案

版本：2026-10-07；对应交付分支：`feature/phase2-feedback`。

这份文件是下一轮设计的基线。它描述当前已实现的玩法、采用这些规则的原因、界面组织方式及扩展入口。参数可调整；未实现的功能不能只通过更新文案就视为已上线。

## 1. 基础与目标

本版直接基于既有 Phase 2 提交 `367138d6f2aa30ff5314e7ba66136a1c9288c648`，针对 Phase 2 试玩反馈增量修改。保留原几何地图、十二个生产单元、三个分区与品种、场景决策、人物观点、延迟报告、审批委派、费用流水、采购、存档及五维复盘；原演示应用的九条路由仍可使用。

设计目标是让玩家在有限信息和有限资源下形成“观察—判断—安排—执行—反馈—复盘”的闭环。重点不是每天点击所有地块，而是决定哪里需要新证据、哪里值得先处理、谁来判断，以及把工作安排在哪一天。

生产单元是独立管理作物、供水和基础设施的最小经营对象。同一单元可以同时存在明确的水分风险、正常作物观测、故障设备或陈旧信息；不把这些维度压缩成一个总评分。

## 2. 一天的操作与反馈

```mermaid
flowchart LR
  A[早会：回顾证据与结果] --> B[判断优先级并排程]
  B --> C[执行：产生行动与观测结果]
  C --> D[日终复盘：对比计划和实际]
  D --> E[次日早会：更新估计并重新安排]
  E --> B
```

早会是唯一正式排程窗口，可以安排今天或未来日期、调整未执行任务、检查容量和预留。执行阶段出现的新问题原则上留到次日早会处理，本版不支持中途重新打开完整排程。玩家主动推进三个阶段；阅读资料、切换页面和语言均不推进时间。

灌溉和人工补水完成后，当天展示预计水分变化；次日结合实际用水、设备效率、天气、蒸散、生长阶段与有效观测更新正式估计。这让玩家看见因果反馈，同时避免把预测改善当作已经确认的安全状态。

## 3. 状态、信息与资源分别管理

| 层 | 变量 | 设计意义 |
| --- | --- | --- |
| 状态 | 作物状态、水分胁迫、设备当前状态 | 当前可能发生了什么 |
| 信息 | 可信度、新鲜度、来源、传感器覆盖、观测时间 | 我们知道多少，依据来自哪里 |
| 资源 | 劳动力、经理注意力、水库存、传感器、设备容量 | 现在和未来能做多少工作 |
| 决策 | 决策者、当时输入、建议、理由、接受状态 | 谁在什么信息下做了什么选择 |
| 结果 | 执行状态、用量、成本、观测与水分影响 | 做了什么，实际发生了什么 |

水分胁迫使用 0–100 的估计和四档颜色：正常、轻度、显著、严重。当前阈值为 25 / 50 / 75，属于可平衡参数；无有效证据时保持未知。趋势实线表示估计，阴影表示基于来源、可信度、新鲜度和传感器覆盖推导的区间，当前并非完整概率模型。

新鲜度从最新有效信息计算，而不只是距人工巡查的天数。水分传感器可刷新水分信息，却不能替代作物与设备巡查。因此水分与作物新鲜度分别显示。可信度不是新鲜度的直接换算：明确高风险与低可信度的“看起来安全”需要不同处理。

设备长期可靠性与当前状态独立。可靠性高的设备仍可能现在故障。系统灌溉依赖正式设备；人工补水消耗更多人力，但可以绕过设备故障。

## 4. 人力、注意力与授权

经理注意力表示亲自投入复杂判断或现场工作的认知资源，不是点击次数。当前默认每天 4 点，早会固定消耗 1；这一点支持回顾和安排多个普通任务。普通排程、页面查看、改期、委派和接受建议不逐项扣注意力。

复杂经理判断进入时消耗 1 点；经理亲自巡查消耗 2 点、劳动力为 0，巡查可信度为 100%。附加现场操作仍正常消耗劳动力。注意力归零仍能继续普通排程、委派给团队或智能助手。

完整班组日当前换算为 8 点劳动力，实际容量受原资源与事件影响，不能结转。田间巡查 1、人工补水 2、系统灌溉/喷施/维修/传感器迁移各 1。因此巡查加人工补水为 3。界面实时计算选定日期的容量、已预约、剩余和冲突；这些数值不是长期锁定的平衡承诺。

角色能力已有扩展入口。经理巡查是本版显式能力，不代表未来经理可以执行所有专业现场工作。后续职业应按角色与能力配置，结合任务资格与资源限制扩展。

## 5. 作业与观测规则

田间巡查同时产生作物与设备观测：作物长势、叶果情况、水分与病害迹象，以及灌溉、阀门、管线、滴头、传感器等部件情况。记录时间、来源、可信度与发现。巡查可以附加人工补水、喷施、维修、移动传感器迁移，也可以单独安排这些动作。

同一生产单元、日期、动作类型必须唯一，组合任务的每个动作也参与查重。重复提示提供查看、改期或取消。尚未执行的任务可保留、改期、取消；取消释放预留、不生成观测，并保留取消记录。改期通过资源与重复检查后原子更新。

固定传感器长期部署；移动传感器通过正式迁移任务更换位置，消耗劳动力。迁移更新位置与历史，之后的有效更新影响该单元水分信息。设备状态、任务执行状态和观测状态是不同字段。

## 6. 决策、委派与历史

普通日常作业可以直接排程，不要求进入决策中心。高风险或高不确定性问题可由经理判断、团队建议或智能助手建议处理。当前团队/助手采用本地可复现规则，读取公开证据、天气、阶段、设备、传感器、资源与已有排程，不调用外部模型服务。

智能助手只提供接受与拒绝，不提供修改。接受不消耗注意力，但仍校验资源和排程。原场景委派保留次日汇报与审批机制；不同入口的汇报时延应在下一轮设计中明确讨论。

历史保留“观测 → 决策 → 作业 → 结果”：当时输入、决策者、建议/决定、理由、可信度、关联任务与执行结果。经理理由可选并保留玩家原文；团队与助手自动生成理由。预测收入与已实现现金继续区分，费用纳入流水与季末复盘。

## 7. 页面与交互结构

| 页面 | 主要用途 |
| --- | --- |
| 农场总览 | 默认状态表，比较风险、作物、信息与设备；切换空间地图同时展示多图层 |
| 今日工作 | 当日注意事项、送达报告、执行反馈、趋势与日记录 |
| 作业排程 | 今天/未来任务、组合动作、容量冲突、传感器、观察日历与作业日程 |
| 生产单元 | 保留原单元浏览与筛选入口 |
| 决策中心 | 复杂问题、不同观点、委派建议、接受/拒绝与决策历史 |
| 经营管理 | 现金、成本、采购、存档和季末经营复盘 |
| 玩法简介 | 六步入门、时间窗口、资源与证据、常见经营情境 |
| 作物知识 | 每种作物的特性、生长周期、经营与市场知识 |

右侧单元板按“状态摘要—信息依据—待执行任务—安排与操作”组织。优先呈现水分值与范围、作物和设备状态、生长阶段、可信度与两类新鲜度。观测详情、专业判断与委派按需展开。任务主按钮进入完整排程，快速巡查保留轻量入口；委派成功后进入决策中心查看建议。长期知识通过百科入口访问，避免把全部说明塞进单元面板。

顶部 EN / 中文切换与原 Demo 共用语言偏好，刷新后保留。翻译只改变展示，不修改模拟状态和已有玩家输入。标识符、随机种子、品牌和品种名称保留必要原文。

## 8. 模块化知识与后续扩展

`src/game/content/gameplayGuide.js` 按模块和卡片配置玩法：稳定 ID、双语标题/正文、列表、可选操作链接。新增玩法可以添加卡片或模块，不必复制页面。

`src/game/content/cropKnowledge.js` 以 CropPack ID 注册作物。每种作物独立提供简介、特性、阶段、经营市场及当前试玩应用章节；`GuideViews.jsx` 自动渲染选择与卡片。当前蓝莓百科包含浅根系、品种气候、果实品质、六个周期阶段、完整成本、上市窗口、渠道和鲜果损耗。

百科知识与模拟能力必须区分。当前百科介绍市场规律，不等于游戏已经实现真实行情、分级、冷链、合同、多年树龄或完整会计。新增作物需要同时补作物包、场景证据/事件、知识卡片和验收；仅添加百科卡片不会生成新模拟作物。

下一轮修改建议先在本文件记录：玩家遇到的具体问题、修改后的行为、影响哪一层、参数变化、旧存档与历史如何解释、验证场景。随后同步代码、入门文案与试玩指南。规则改变不应只调整 UI；新增真实状态不能直接泄漏到玩家可见证据。

优先可探索：任务排程易用性、事件与资源平衡、团队建议质量、阶段敏感性、角色能力与决策效果统计。更多作物、外部 AI、科学不确定性模型和市场物流模拟需分别明确范围。

## 10. 验收与 PC 试玩

当前验收：109 项自动测试通过；生产构建通过；lint 无新增问题；完整 28 天、原九条演示路由、六个旧场景及八个视图双语浏览器检查通过。详见 [验收记录](validation/phase2-feedback-results.md)。原有大包警告和 lint 历史问题仍存在。

PC 安装 Node.js 20.19+ 或 22.12+，在最新版分支代码目录执行：

```sh
npm ci
npm run dev
```

打开终端显示的 Local 地址并加 `/game`，通常为 `http://localhost:5173/game`。保持终端运行。若端口被占用，以实际输出为准。GitHub 源码 ZIP 与截图 ZIP 是不同文件；源代码 ZIP 可解压后按同样步骤启动。

重验：`npm test`、`npm run build`、`npm run lint:baseline`；有 Chromium 时运行 `npm run test:acceptance` 与 `npm run test:game:locale`。最新六张完整中文界面截图位于 [screenshots/latest](validation/screenshots/latest/)。
