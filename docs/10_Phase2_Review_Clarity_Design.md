# Phase 2 试玩反馈：阶段知识与日终复盘

日期：2026-10-09。基线：main `4c4b6356a26b415bfba87d3d74f02317f2affd3f`，承接 [经理操作流程设计](09_Phase2_Manager_Flow_Design.md)。本轮根据玩家确认的五项方案实施。

## 目的与操作流程

玩家查看生产单元时，应能直接理解它的状态与生长阶段；执行后，应能快速核对任务是否成功、消耗了什么、发现了什么。保留已有 Phase 2 的场景、资源平衡、每日两次推进、多选排程、委派、信息边界、存档及季末复盘。

早会查看已知信息 → 安排今天或未来任务 → 开始执行并停在日终 → 表格核对结果 → 次日早会重新安排。阅读知识、切换语言与打开结果详情均不消耗资源或推进时间。

## 五项修改

1. 巡查反馈采用完整的双语标签：中文“作物状态／设备状态”，英文“Crop condition／Equipment condition”。不再出现“作物 Condition”。
2. PU、报告、简要指南和百科共用阶段名称；从 PU 点击知识入口，携带单元及最新已知阶段，自动滚动并突出对应卡片。左侧菜单仍打开完整百科。阶段未知时不选中任何阶段，并提示巡查或等待有效报告。
3. 界面天气温度统一保留一位小数，覆盖今日、次日和决策输入历史。缺失值显示“—”，零温度显示“0.0°C”。内部天气计算继续使用原始精度。
4. 待处理决策卡移除重复的劳动力与注意力摘要。顶部资源栏与排程报价保留，天气摘要继续显示。
5. 日终及次日昨日反馈共用表格：生产单元、作业、执行状态、资源消耗、关键结果。每个任务一行，任务与单元可直接打开；详细观测与执行记录默认折叠。

## 阶段与知识对应

| 阶段 ID | 中文 | English | 内容重点 |
|---|---|---|---|
| vegetative | 营养生长期 | Vegetative | 新梢、根系、叶色与稳定根区环境 |
| flowering | 开花期 | Flowering | 花部健康、授粉与供水稳定 |
| fruit_set | 坐果期 | Fruit set | 幼果保留与早期膨大、果径、缺水风险 |
| ripening | 转熟期 | Ripening | 着色、硬度、裂果和品质 |
| harvest | 采收期 | Harvest | 适收窗口、果实健康及背景经营安排 |

当前模拟的 `fruit_set` 包含早期果实发育，卡片明确说明这一点，不改变阶段阈值。`harvest` 原被写成采后恢复，现纠正为采收期；采后恢复单独放在延伸知识模块，休眠知识也仍是百科背景，不新增可执行阶段。采摘、物流和销售内容不意味着这些动作已经可以在游戏中执行。

每个可玩阶段包含七个独立字段：正在发生什么、水分敏感点、病虫害关注点、巡查重点、当前管理优先级、常见误判、经营安排。实际时期仍因品种、地区和栽培方式而异，不固定到月份。

知识定位只使用玩家最新已送达的阶段报告，显示报告日期。不能用隐藏作物状态替玩家确认阶段。信息新鲜度规则保持：一次巡查同步更新水分、作物和设备；传感器随后可以独立更新水分，因此两类信息的日期可以不同。

## 实际结果与预计影响

资源消耗取执行记录：劳动力取本次结果；用水取 `actualOutput.waterConsumed`；费用取实际 `cost`。不从计划用水或预计费用替代实际消耗。受阻任务显示零消耗；已执行但失败的任务仍展示实际发生的劳动与费用。人工补水的有效到达水量和库存消耗是不同概念，表格用水列展示库存实际消耗。

多个单元共享的任务只展示一行，列出涉及单元；总消耗只统计一次。巡查和附加操作仍属于同一任务。作物与设备条件属于巡查当时的发现，修复后的执行结果在详细记录中保留。

灌溉后的水分变化标记为“预计”，注明次日正式更新且尚未确认恢复。次日同时显示新的正式估计。表格标注作业发生日期，不把昨天的结果改成今天。横向滚动限制在表格容器内，移动端页面不因表格变宽。

## 实现与扩展入口

- `src/domain/growthStages.js`：共用双语阶段名称；CropPack 的阶段计时与风险参数保持原位。
- `src/game/content/blueberryStages.js`：蓝莓分阶段知识字段；`cropKnowledge.js` 继续按 CropPack ID 注册作物及章节。
- `src/game/GuideViews.jsx`：模块化卡片、阶段字段、单元上下文与自动定位。增加新作物时可提供独立阶段卡片和经营章节。
- `src/game/displayFormat.js`：温度显示格式。
- `src/game/dailyReview.js`：执行记录到表格行的纯投影，兼容原有存档字段。
- `src/game/FeedbackViews.jsx`：复盘表格、汇总与详情；`GameApp.jsx`：知识入口与简化的待处理决策。
- `src/game/localization.js`：共用阶段名称，并在显示时兼容旧报告中的阶段标签；不重写历史存档。

验证入口：`npm test`、`npm run lint:baseline`、`npm run test:game:locale`、`node scripts/smoke-review-clarity.cjs`、`npm run test:acceptance`、`npm run build:pages`、`npm run test:pages`。具体结果见 [本轮验收记录](validation/review-clarity-results.md)。
